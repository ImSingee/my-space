# Drizzle

The platform database uses Drizzle ORM v1 with PostgreSQL through
`postgres-js`.

## Database structure

- `src/db/schema.ts` contains the platform tables and re-exports the generated
  Better Auth tables.
- `src/db/auth-schema.ts` is generated by `pnpm auth:generate`; do not edit it
  manually.
- `src/db/relations.ts` builds the complete RQB v2 relation definition from the
  platform schema and Better Auth's generated relation part.
- `src/db/db.ts` creates the production client. `src/db/test-db.ts` creates the
  PGlite test client with the same relations.
- `migrations/` contains Drizzle Kit v3 migration folders.

Platform tables use `snakeCase.table`, so TypeScript properties such as
`currentDeploymentId` map to PostgreSQL columns such as
`current_deployment_id`. Better Auth's generated schema declares its database
names explicitly.

## Relational queries

RQB v2 uses object filters and object ordering:

```ts
const runs = await db.query.agentRuns.findMany({
  where: {
    sessionId,
    status: { in: ['queued', 'running'] },
  },
  orderBy: { createdAt: 'desc' },
});
```

Use `AND`, `OR`, and `NOT` for compound filters. Use `RAW` only when a filter
cannot be expressed by the object API. The SQL query builder API is unchanged;
calls such as `db.select().from(table).where(eq(table.id, id))` should continue
to use Drizzle SQL expressions.

## Migrations

Each migration has this layout:

```text
migrations/
  YYYYMMDDHHmmss_name/
    migration.sql
    snapshot.json
```

Create a migration after changing `src/db/schema.ts`:

```sh
pnpm migrations:generate
```

Validate the migration history without connecting to PostgreSQL:

```sh
DATABASE_URL=postgres://unused:unused@127.0.0.1:1/unused \
  pnpm exec drizzle-kit check --config drizzle.config.ts
```

Do not rename, reorder, delete, or rewrite an applied migration. The v1
migrator identifies migrations by their folder name and retains the SQL hash in
`drizzle.__drizzle_migrations`.

Migrations run automatically during platform startup through
`src/nitro/plugins/migrate.ts`. `src/db/migrate.ts` verifies the v3 folder
layout, obtains the platform advisory lock, and then invokes the Drizzle
migrator. `pnpm migrations:apply` is available for an explicit migration run.

When an existing database still has the legacy three-column migration ledger,
Drizzle v1 upgrades it by adding `name` and `applied_at`. The converted v3
folders keep the original SQL hashes and timestamps, so already-applied
migrations are matched instead of replayed. This compatibility path is covered
by `src/db/drizzle-v1-migration.test.ts`.

`DATABASE_URL` is required by both the application client and
`drizzle.config.ts`.
